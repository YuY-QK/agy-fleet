# agy-fleet AI 开发规则

本文件写本项目特有的执行细则，补充根目录 `AGENTS.md` 和全局约定。冲突时以用户当前指令和已确认的方案为准。

## 1. 当前阶段

M1：单账号前台 `run_task` 已实现。多账号与租约、后台/等待、续聊、取消/关闭、账号命令、`doctor`、编排 prompt 均未实现，不要描述为已有能力。阶段划分见 `docs/PLAN_v1.1.md` §9，一次只做一个阶段，阶段结束停下等确认。

## 2. 范围控制

- 工作进程不 commit、不 push、不合并；这些由调用方决定。
- 不做规避额度或风控的任何处理；不做自动改派、自动重试。
- 权限规则只来自代码/配置，不接受 MCP 工具参数放宽。

## 3. 项目约束

- agy 与 ACP 的行为以 `docs/acp-验证结论.md` 的实测为准；不要照搬面向通用 agent 的假设。
- 账号路径、用户目录等机器相关信息只通过配置/环境变量传入，不写进仓库。
- 依赖只选发布满两周的版本并锁定（`pnpm-workspace.yaml` 的 `minimumReleaseAge`）。
- stdout 是 MCP 传输，服务器日志一律写 stderr。
- 文档、注释、提交信息用简体中文；标识符用英文。
- 代码必须是自己写的：不复制、不改写第三方项目的代码；若将来确需引入第三方代码，先在 `NOTICE` 保留其版权与许可文本，并告知项目负责人。

## 4. 核心不变量

- 编辑类权限请求：所有路径解析符号链接与 `..` 后都在本任务 worktree 内才允许，`.git` 内一律拒绝。
- 命令类及其他类别一律拒绝；选项只回答 `allow_once` / `reject_once`。
- 每次拒绝都进入任务结果的 `denied`（agy 被拒后常空回复，必须由我们汇报）。
- 不使用 `--dangerously-skip-permissions`。

## 5. 测试与验证

- 权限判定必须覆盖：worktree 外绝对路径、`..` 逃逸、指向外部的符号链接（目录/文件/悬空）、`link/..` 的真实语义、`.git`、命令、其他类别。
- ACP 交互后续用模拟 agent 做回放测试；真实账号只用于人工验收。
- 人工验收：派一个新建文件的任务与一个触发命令执行的任务，确认汇报、diff、`denied`。
