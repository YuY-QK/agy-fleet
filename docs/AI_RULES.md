# agy-fleet AI 开发规则

本文件写本项目特有的执行细则，补充根目录 `AGENTS.md` 和全局约定。冲突时以用户当前指令和已确认的方案为准。

## 1. 当前阶段

M3：在 M2（多账号与租约、后台/等待、续聊、取消/关闭、错误分类与暂停）之上，已实现 `config.yaml`、命令白名单与 `outside_policy`（含 elicitation 询问）、`account add|login|list|resume|remove`、`doctor`、macOS 独立钥匙串。`run_task` 的 `isolation`、编排 prompt、npm 发布未实现，不要描述为已有能力。阶段划分见 `docs/PLAN_v1.1.md` §9，一次只做一个阶段，阶段结束停下等确认。

## 2. 范围控制

- 工作进程不 commit、不 push、不合并；这些由调用方决定。
- 不做规避额度或风控的任何处理；不做自动改派、自动重试。
- 权限规则只来自代码/配置，不接受 MCP 工具参数放宽。

## 3. 项目约束

- agy 与 ACP 的行为以 `docs/acp-验证结论.md` 的实测为准；不要照搬面向通用 agent 的假设。
- 账号路径、用户目录等机器相关信息只通过配置/环境变量传入，不写进仓库。
- 依赖只选发布满两周的版本并锁定（`pnpm-workspace.yaml` 的 `minimumReleaseAge`）。
- stdout 是 MCP 传输，服务器日志一律写 stderr。
- 文档、注释、提交信息用简体中文；标识符用英文。
- 代码必须是自己写的：不复制、不改写第三方项目的代码；若将来确需引入第三方代码，先在 `NOTICE` 保留其版权与许可文本，并告知项目负责人。

## 4. 核心不变量

- 编辑类权限请求：所有路径解析符号链接与 `..` 后都在本任务 worktree 内才允许；路径里有任何 `.git` 段、落在 agy-fleet 数据目录/配置/账号库/账号 HOME 内的，无论 `outside_policy` 都直接拒绝。
- 命令类：命中配置文件的白名单才允许；匹配只接受朴素的“词序列”，任何 shell 控制、展开、通配、换行、变量赋值都视为不命中（规则见 PLAN §6.5，实现 `policy/commands.ts`）。
- 规则外的操作按 `outside_policy`：`deny` 拒绝；`ask` 经 elicitation 询问，只有用户明确选“允许”才放行，其余（拒绝、超时、不支持、出错）都拒绝。选项只回答 `allow_once` / `reject_once`。
- 每次拒绝都进入任务结果的 `denied`，经用户批准的进入 `approved`（agy 被拒后常空回复，必须由我们汇报）。
- 钥匙串：只用 `HOME=<账号HOME>` 操作账号自己的钥匙串；建钥匙串与登录前后比对本人真实钥匙串，有变化只报告、绝不自动修复；测试只用临时 HOME。
- 不使用 `--dangerously-skip-permissions`。

## 5. 测试与验证

- 权限判定必须覆盖：worktree 外绝对路径、`..` 逃逸、指向外部的符号链接（目录/文件/悬空）、`link/..` 的真实语义、`.git`、命令、其他类别。
- ACP 交互用模拟 agent（`src/acp/mock-agent.fixture.mjs`，行为由 `MOCK_MODE` 等环境变量控制）做回放测试；真实账号只用于人工验收。
- 租约、账号库等跨进程逻辑用真实文件系统和多个真实进程测试，不 mock 文件系统。
- 命令白名单必须覆盖组合命令绕过（`&&`、`;`、管道、子 shell、重定向、换行、`$()`、反引号、变量赋值前缀）。
- 钥匙串相关测试只在 macOS 上跑，用临时 HOME，并断言本人钥匙串前后不变。
- 人工验收：派一个新建文件的任务与一个触发命令执行的任务，确认汇报、diff、`denied`；`account add` 的真实登录与 `ask` 弹窗由项目负责人亲自操作。
